# ADR-007: Protección de la invariante de agregado para el límite de butacas por usuario

## Estado

Aceptada.

## Contexto

`RET-007` establece que un usuario no puede poseer más de cuatro butacas
ocupantes (`ACTIVE` o `CONFIRMED`) para un mismo evento. A diferencia de
`RET-001`, que protege la unicidad de una fila por evento y butaca, esta regla
evalúa un conjunto de retenciones del mismo usuario y evento.

## Decisión

La validación se realizará antes de la inserción, en la coordinación del caso
de uso mediante una consulta al repositorio: contará las retenciones ocupantes
actuales del usuario para el evento y considerará el lote solicitado. Si el
total supera cuatro, la operación conjunta se rechazará atómicamente con una
excepción de dominio, que la API traducirá a `409 Conflict` con el código
`USER_HOLD_LIMIT_REACHED`.

Las retenciones `ACTIVE` y `CONFIRMED` computan para el límite. Las que estén
en `EXPIRED` o `RELEASED` no computan, de acuerdo con `RET-002`.

## Alternativas descartadas

1. **Índice único en PostgreSQL.** No permite expresar una restricción basada
   en el conteo de un conjunto de filas.
2. **Bloqueo pesimista o serialización de transacciones (`SELECT FOR UPDATE`).**
   Se descarta en esta etapa por su complejidad operacional.

## Consecuencias

- La regla queda protegida en la capa de aplicación para los casos de uso
  estándar, preservando la atomicidad del lote.
- Bajo concurrencia extrema, dos solicitudes simultáneas del mismo usuario
  podrían observar el mismo conteo y superar el límite. Esta condición de
  carrera se acepta explícitamente mientras no se adopte un mecanismo de
  serialización.
- El Frontend responde al código estable `USER_HOLD_LIMIT_REACHED` y no necesita
  conocer la constante numérica.
